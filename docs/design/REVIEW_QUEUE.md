# Очередь визуальной проверки · снимок 3.2.89 до патча PIN/автоскрытия

Это список маршрутов для телефона. Визуальные симптомы подтверждаются только на реальном экране. Для каждого результата добавить сборку, настройки темы/шрифта и итог, чтобы не открывать тот же вопрос через неделю.

|---|---|---|---|
| 1 · эталон | Настройки безопасности → справка об ограничениях PIN | В базе `SecurityFragment` создаёт обычный `MotionDialogBuilder` напрямую; `security_limits_summary` — один ресурс на 372 знака. Есть отдельный патч двух экранов. | На ветке внедрения проверить текст, кнопку «Закрыть», возврат и старый режим. Не делать второй редизайн. |
| 1 · эталон | Автоскрытие → редактировать правило с выражением | `AutohideFragment` уже вызывает стандартный builder, но передаёт свою форму. Один поиск конструкторов эту проблему не найдёт. | Пустой тест не выдаёт совпадение, с открытой клавиатурой видны ввод и сохранение. Сравнить с отдельным патчем, не трогать быстрый фильтр. |

**Первая инвентаризация:** 1214 производственных Java/Kotlin/XML-файлов в перечисленных сканером каталогах, 179 сигналов в 82 файлах. В том числе 6 прямых вызовов конструктора (один внутри самой фабрики), 56 случаев собственного view/title, 53 явных размера текста, 28 фиксированных цветов, 29 длинных строк RU, 7 собственных поверхностей. Один экран может давать несколько сигналов, а многие находки допустимы. В комплекте для передачи есть `INVENTORY_3.2.89.csv` (путь и строка на каждую запись); для актуальной ветки переснять.

**Что автоматом не видно:** размеры после OEM-разметки и масштабирования, реальные темы, клиппинг, неудачная группировка, управление фокусом, качество текста даже в короткой фразе, доступность редких веток и ошибки перехода между состояниями. Вести список проверок по *пользовательским сценариям*, включая те, по которым в CSV нет совпадений.

**Как покрыть остальной интерфейс по очереди:** (1) настройки и вторичные диалоги, (2) чтение: список, тред, шторка, избранное, FAB, (3) постинг: ввод, капча, вложения, конвертация, (4) медиа и редакторы, (5) онбординг, ошибки, разрешения, восстановление состояния. Для каждой группы фиксировать точки входа и состояния: без данных, загрузка, успех, ошибка, отмена, где применимо. Если визуальная причина повторилась на двух экранах, сверить общего владельца и чинить его один раз. Не считать всякую функциональную проблему редизайном.
